# TMS v2 — V1 Design

A truth maintenance system built entirely from text-based statements: a number-free epistemic ledger that agents can query for belief states, backed by evidence and sources, served over MCP.

---

## The Discipline

This system stores and reasons over **text-based statements only**. These rules are non-negotiable and apply to every layer:

1. **No numbers, no degrees — not even qualitative ones.** No probabilities, likelihoods, weights, scores, rankings, or ordered labels ("weak / moderate / strong"). An ordered label set *is* a number set — `weak/moderate/strong` is `{33%, 66%, 100%}` in disguise — which is why this document avoids the word "qualitative": qualitative scales are still scales, and this system's currency is *statements*, not points on any scale. The moment you aggregate ordered labels, you are doing arithmetic on them, and you have rebuilt naive Bayes with worse ergonomics.
2. **Never aggregate.** Conflicts are resolved by **graph topology**, not weighted summation. There is no "how much support exists" — only "which chains of support survive against which chains of attack."
3. **Contested is an answer.** When the argument graph cycles, the system says so and shows both sides. It never numerically smooths a paradox.
4. **Claims may contain numbers; the system never computes with them.** "The company laid off 15% of staff" is a legitimate claim. A rating of confidence in that claim is not legitimate input to any evaluation.
5. **Numbers may be computed *from* the graph by external layers, but never stored *in* it.** (See [Layering](#8-layering-the-stack).)

---

## 0. The Base Layer: A Ledger, Not a Triple Store

The base layer is deliberately opinionated and minimal. It is **not** a generic statement store. Triple stores, entity graphs, and ontologies are things you *build on top of it* — never things it *is*. Three rules keep it honest:

1. **Claims are opaque text.** The base layer never decomposes a claim into subject/predicate/object, never extracts entities, and never structures what a claim is *about*. Parsing claims is a job for a layer above. Identity resolution lives up there too — which is why it can never poison the base.
2. **The vocabulary is fixed.** Exactly four node types and a handful of edge types — no user-defined predicates, no schema-in-data, no ontology hooks. New semantics mean a new layer, not new primitives.
3. **Evaluation reads topology, never claim internals.** The evaluator decides whether a claim is believed by walking evidence edges alone — it never needs to know what the claim "says." This is what makes opaque claims safe, and it is why text-only claims suffice.

**Why not just use a triple store as the substrate?** A triple store is maximally generic — any predicate, open-world semantics, opinions about nothing. But a truth maintenance system's entire value is its opinions: what counts as evidence, what belief means, how conflict resolves. A triple store stores everything and believes nothing. The opinions are the product.

**Why the base can be this simple: the boundary is agentic.** An intelligent agent sits at the write path (ingestion) and at the read path (querying). The system's job is to be a legible ledger — storage plus topological evaluation — and interpretation of text is always the agents' job. The general rule: **type only what the system must itself reason over; store as text everything an agent can read.** Time (§6) is the next case in point.

*A note on Evidence-as-node:* yes, evidence could have been a plain edge between observation and claim. It's a node for exactly one reason: the link itself must be attackable (§2). That's **reflexivity**, not genericity — no crack in the rules above.

## 1. Core Idea

- The **ledger** (claims, observations, sources, evidence) is append-only and immutable.
- A **world state** is not stored — it is a *query*: the set of claims whose status is `believed` (plus contested/unresolved, so the boundary of belief is visible) at a point in time, for a set of filters.
- **Statuses are derived at query time.** Nothing is stored but facts; belief is recomputed from the evidence graph on demand. The write path is a pure append — zero side effects, nothing ever needs invalidation.
- Everything is a claim: sources, verdicts, identity statements, independence claims. All first-class, all attackable. The system is fully **reflexive**.

## 2. Data Model (Neo4j)

Node types:

| Label | Meaning | Key properties |
|---|---|---|
| `Claim` | A statement. The atomic unit. | `text`, `asserted_at`, `embedding`, `embedding_model` |
| `Observation` | A document: tweet, paper, repo, blog, report. Immutable once written. | `uri`, `doc_type`, `content_ref`, `content_hash`, `asserted_at`, `embedding`, `embedding_model` |
| `Source` | Where an observation came from. | `name`, `uri`, `source_type` |
| `Evidence` | A **reified edge**: an assertion that an observation bears on a target, with a reason. Reified because we need edges to target it (undercutting attacks). | `relation`, `reason`, `asserted_at` |

Relationship types:

| Edge | Connects | Meaning |
|---|---|---|
| `PUBLISHED` | `Source → Observation` | provenance |
| `FROM` | `Evidence → Observation` | which document grounds this evidence |
| `TARGETS` | `Evidence → Claim \| Evidence \| Source \| Observation` | what it bears on |
| `SAME_AS` | `Claim → Claim` | asserted co-reference, with `reason` |
| `DUPLICATE_OF` | `Observation → Observation` | syndication/dependence (independence tracking) |
| `SUPERSEDES` | `Observation → Observation` | document versioning |

**Evidence relations** (`Evidence.relation`):

- `SUPPORTS` — the observation is grounds for the target
- `REBUTS` — the observation is grounds against the target
- `QUALIFIES` — the observation adds a condition/caveat to the target (v1: targets Claims only)

**The attack class is determined by what is targeted** (classic argumentation distinction, for free):

- REBUTS a `Claim` → *rebutting*: attacks the claim itself
- REBUTS an `Evidence` node → *undercutting*: attacks the link ("this observation was misread")
- REBUTS a `Source` → *undermining*: attacks the origin ("this outlet fabricates")
- REBUTS an `Observation` → attacks the document's integrity directly

**Why `reason` is required:** the reason field is the entire payload of the system — the "why" in plain language, in the system's own words. "Supports weakly" is forbidden; "supports because the 10-Q states the layoffs on page 3" is the only kind of statement allowed. Reasons must be specific and checkable.

**Note on why Evidence is a node, not an edge:** a property graph cannot attach an edge to an edge. Reifying evidence gives the link itself an identity that can be attacked, embedded, and queried. This is a feature, not an accommodation.

### Nothing derived is ever stored

There are no status properties on any node. `status`, `chains`, `independent_sources`, and `collapse_conditions` exist only as query results (§3). No belief can ever be stale, because no belief is ever stored.

## 3. Statuses and Evaluation

```
unresolved   no standing support, no standing attack
believed     standing support, no standing attack
disbelieved  standing attack, no standing support
contested    standing support AND standing attack (incl. attack cycles)
```

**Evaluation is grounded-semantics fixpoint over the evidence graph** (Dung, 1995):

1. Evidence with no attackers stands.
2. Evidence attacked only by standing evidence falls.
3. Iterate to fixpoint.
4. Cycles that never resolve → `contested`. This is correct, not failure.

No aggregation occurs anywhere. Conflict resolution is purely topological.

**When evaluation runs: at query time, always.** No statuses are stored anywhere; every query re-derives belief from the evidence graph. This trades per-query cost for total simplicity — no cache invalidation, no stale beliefs, no consistency bugs, one code path. The ledger contains facts, full stop. If evaluation cost ever matters, materialization becomes a transparent cache *inside* the evaluator — never a stored field, never visible to writers or readers.

**Bootstrap state:** with no evidence, every claim is `unresolved`. Belief accrues only from asserted evidence — the system believes nothing at time zero.

## 4. Verdict Shape

Everything that returns a judgment returns this structure — never a score:

```json
{
  "claim": "…",
  "status": "believed",
  "support": { "chains": 3, "independent_sources": 2 },
  "grounds": [
    { "evidence_id": "…", "reason": "…", "from": "observation_291 (Reuters, 2026-08-30)" }
  ],
  "surviving_objections": [],
  "collapse_conditions": [
    { "retract": "observation_291", "flips_to": "unresolved" }
  ],
  "computed_at": "2026-10-04T13:20:00Z",
  "as_of": "2026-10-04T13:20:00Z"
}
```

- `support` is reported as **structure**, not score: "you would have to refute all three chains" — resilience, not probability. `independent_sources` respects `DUPLICATE_OF` edges, so syndication is never mistaken for corroboration.
- `collapse_conditions` is this system's answer to "how confident?" — v1 computes **single-retraction flips only** (retract one node, re-evaluate, report if status changes). Minimal cut sets are a deferred refinement.

## 5. Identity Without Entities

**There are no entity nodes.** Deliberate. Entities are ontology, and ontologies are where truth-maintenance projects go to die — every entity node is an identity claim you must defend, merge, and split forever.

Instead:

- **Identity is asserted, never assumed.** `"the 'Sam' in this tweet is Sam Altman"` is a claim like any other, attackable by evidence like any other. The system reasons about co-reference instead of hard-coding it.
- **Retrieval is semantic.** "All claims about X" is an embedding-similarity query over `Claim` embeddings — never an exact-match join on an entity key.
- **Co-reference, when the agent is confident, is recorded** as a `SAME_AS` edge with a reason. When unsure, do nothing; fuzziness is handled at query time, not by minting entities.
- **An alias table is not needed in v1.** It is a performance cache for exact surface-form lookup. If `SAME_AS` edge churn ever becomes annoying, add it then — as an optimization, not a semantic layer.

**Honest cost:** semantic retrieval means topic result sets are *plausible matches*, never guaranteed exhaustive. This is documented behavior, not a bug. Agents should treat "no results" as "nothing above similarity threshold," not "system asserts nothing else exists."

**Embedding discipline:** every node/edge embedding stores its `embedding_model`. Numeric aggregation layers must know what they're reading; model versions are part of the data.

## 6. Time

One clock, no more:

- **`asserted_at`** — when a claim, observation, or piece of evidence entered the system. The only typed temporal field in the entire schema. Set by the system, never by an agent. (All node types use the same name for it.)

Everything else temporal stays in text, where an LLM reads it natively:

- **Claim time is claim content.** "Layoffs happened in September 2026" stays inside the claim text, undecomposed. By the opacity rule, event-time extraction is a projection (L2), exactly like entity extraction or triple-ification.
- **WHEN vs WHAT.** The base layer does not separate "when this was supposedly true" from "what is being said" as first-class structure. When the when matters, the ingesting agent folds it into the claim text at write time: *"X had 800 employees, per the October 2026 filing."* Separation of concerns is achieved by convention, not schema.
- **Temporal reasoning is agent-asserted.** "These two claims concern different timeframes" is a `REBUTS` edge the agent writes, like any other. The evaluator never interprets time; it walks topology.
- **`as_of` is a query parameter, not a snapshot.** "World state as of October 1" = evaluate the graph over evidence where `asserted_at ≤ as_of`. Time travel is query scoping; the ledger is the only store.
- **Belief time ≠ claim time.** "As of October 1" answers *when we believed it*, filtered by `asserted_at`. What the claim is about stays in its text. The system maintains beliefs about time; it does not maintain timed beliefs.
- **Append-only.** Corrections are edges (`SUPERSEDES` for documents) and new claims with their own provenance — never mutations.
- **State claims decay by contradiction, not by timer.** "X is CEO" stays believed until a contradicting claim arrives. Timer-based decay is out of scope for v1.

**What we gain:** no temporal ontology in the base. Single moment vs period vs open-ended vs recurring vs approximate ("around September") is a rabbit hole — every typed primitive forecloses the others (see: Allen's interval algebra). Text defers the whole mess to whoever wants structure later.

**What we honestly lose:** structural event-time queries ("all claims about 2019") in v1. If that hurts in practice, the fix is an L2 extraction layer, not base primitives.

**Deferred:** retroactive corrections ("announced Sept 3, began Oct 1"), prediction-vs-outcome modeling, mechanized temporal consistency checking. If ever wanted, that last one is a layer — L1 evaluates topology only, so a temporal-logic layer composes cleanly.

## 7. MCP Surface (v1)

| Tool | Purpose |
|---|---|
| `add_source` / `add_observation` / `add_claim` / `add_evidence` | Write path. `reason` required on evidence. |
| `check_statement(text, as_of?)` | Full pipeline: normalize → semantic match → evaluate → verdict + trace. Unknown statements register as new `unresolved` claims. |
| `world_state(query?, status?, as_of?, min_chains?)` | The believed/contested/unresolved slices for a filter. `min_chains` filters by structural resilience. |
| `why(claim_id)` | Full support/attack chains with reasons. |
| `what_if_retracted(node_id)` | Counterfactual: which statuses flip if this node falls. |
| `diff(as_of_a, as_of_b)` | Which beliefs changed between two points, and via which evidence. |

## 8. Layering: The Stack

The layering contract: **each layer reads what's below it and writes back only via claims.**

- **L0 — The Ledger** (this document). Claims, observations, sources, evidence. Append-only; opinionated about structure, silent about claim content.
- **L1 — The Evaluator** (this document). Statuses and verdicts over L0 topology, computed at query time. Writes nothing, ever.
- **L2 — Projections** (anyone, later). Derived stores, read-only over L0/L1:
  - **A triple store**: parse claim text into subject-predicate-object triples; project evidence nodes into reified statements. The base layer's job is to make this possible — claims are text, reasons are text, topology is addressable — never to *be* it.
  - **An entity graph**: cluster claims by co-reference; materialize `SAME_AS` assertions into entity nodes with their own identifiers.
  - **Numeric aggregators** (Bayesian, fuzzy, betting markets, committee votes): read topology, reasons, timestamps, independence via `DUPLICATE_OF`, embedding model versions — derive scores out-of-band, in their own stores.
  - **Write-back rule**: a layer that wants to record its output records it as a *claim with provenance* ("layer X rates this belief 0.72") — which is then attackable evidence like everything else. Numbers may be computed *from* the graph; they are never stored *in* it.

The base layer's API contract is what makes layers safe to build: opaque claims, a fixed vocabulary, and topology-only evaluation mean projections don't break when the base evolves.

## 9. V1 Scope

**In:** everything above.

**Out (parking lot of deferred hard problems):**

- Entity nodes / alias tables — revisit if semantic recall demonstrably fails
- Multiple belief contexts (v1 has one implicit default context; design does not block adding `Context` nodes)
- Minimal cut sets for collapse conditions
- Temporal decay heuristics; event-time extraction/filtering (an L2 projection)
- Adversarial injection defenses (v1 trusts the writing agent)
- Attacking a `SAME_AS` edge directly (v1: reify the edge into a claim if this becomes necessary)
- Status materialization / evaluation caching — explicitly deferred; if ever needed it lives *inside* the evaluator as a transparent cache, never in the write path

## 10. Worked Example

An agent ingests a Reuters article (observation `o1`, source `reuters.com`) and a skeptical blog post (observation `o2`, source `example.org`):

```
claim c1:  "Tesseralia laid off 15% of staff in September 2026"

evidence e1: o1 SUPPORTS c1  (reason: "Reuters cites the internal memo dated 2026-09-20")
evidence e2: o1 SUPPORTS c1  (reason: "Two employees confirmed on the record")
evidence e3: o2 REBUTS c1   (reason: "Blog claims memo is fake, cites metadata anomalies")
evidence e4: o3 REBUTS o2   (reason: "Independent analysis of the memo PDF authenticates it")
```

Evaluation: `e4` stands (nothing attacks it) → `e3` falls → `e1`, `e2` stand → **c1 = believed.**
Collapse conditions: retracting `o1` flips c1 to `unresolved`. If a second attack survived, c1 would be `contested` — and the verdict would say so, with both sides, rather than picking a number.

## 11. Stack

- **Database:** Neo4j Community Edition, local, Docker. (Vector indexes on nodes and relationships are native.)
- **Server.** `reason` required everywhere. Embeddings stored with `embedding_model` pinned.
- **Rationale vs. alternatives:** FalkorDB and Memgraph are credible (both Cypher-compatible; Memgraph community edition includes vector search); Kuzu is archived (Oct 2025, team acqui-hired by Apple — forks LadybugDB/Bighorn exist but are immature). Neo4j wins on maturity, native vector indexes, and familiarity. **Trade-off to remember:** Neo4j is a server process — if this MCP server is ever distributed to non-technical users, an embedded store (SQLite) would be the fallback target, and the data model here is portable to it.
